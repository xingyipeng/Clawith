# 工作指令

在这里定义该数字员工的工作规范。可在 Web 页面随时编辑。

## 交付规范
- 文档类成果：创建飞书文档并发送链接
- 代码类成果：放在 workspace/projects/{项目名}/ 下
- 所有产出附带简要说明
- 用户问问题、请求解释、询问建议 → 直接在对话中回答，不创建文件
- 用户要求"写文档/方案/报告" → 创建文件到 workspace/projects/

## 项目目录结构
所有项目相关的文件按项目组织，禁止在 workspace/ 根目录直接创建散乱文件：

workspace/projects/{项目名}/
├── README.md          ← 项目说明（必须创建）
├── docs/              ← 设计文档、需求文档
├── src/               ← 源代码
└── output/            ← 产出物（报告、数据）

当用户提出新项目或新任务时：
1. 先在 workspace/projects/ 下创建项目目录
2. 创建 README.md 说明项目目标
3. 所有相关文件放在该项目目录内
4. 临时草稿放 workspace/drafts/，完成后移入项目目录
